# 成员 C：界面、线程与验收

关联 [Issue #3](https://github.com/We1chan/campus-print-scheduler/issues/3)。

## 老板桌面端与学生网页

`campus-print` 默认打开老板端（`--role boss`）。四页店主端的功能见 [merchant-frontend.md](merchant-frontend.md)，旧老板控制台由 `--classic-owner` 打开。

学生使用 `tools/classroom/` 网页，HTTP 网关为 `tools/classroom_web.py`。网页提供文件上传和预览、后台报价、模拟支付、本人订单与匿名队列；通过同一数据目录连接共同 coordinator。Windows 启动入口为 `start-classroom-demo.ps1`，完整步骤见 [classroom-demo.md](classroom-demo.md)。

旧 `StudentWindow`、C++ 文档预览与纸叠动画已移除。`PrintController`、`PrintWindow`、纸张任务示意和 `editorial_chrome.*` 继续用于老板端。以下说明主要记录旧老板控制台的经营与课程演示功能；不会重新打开学生桌面窗口。

预计时间全部来自后台快照与报价，界面只负责措辞；派发暂停时显示相对时长。规则与边界见 [shop.md](shop.md) 和 [interfaces.md](interfaces.md)。

运行中的完成预估以最近一次实际页进度的观察时间为锚点，两次进度之间持续扣除经过时间，避免每次轮询把完整剩余页耗时加回去。暂停队列的相对等待使用后台 `forecast_at_ms`，不会因一秒缓存刷新而来回倒数；真实延迟、worker 重启或队列配置变化仍会更新预估。

长队列超过预测上限或部分订单因缺纸、设备暂停而无法预计时，完整队列的清空时间显示“暂无法预计”，不会把前一部分订单的预计完成当作全队列清空，也不会在学生端误显示“无需等待”。

## 当前可运行功能

两台打印机分别显示文档、尝试状态与页数进度；任务表按 `job_id` 关联，支持等待/运行/完成/失败/取消筛选。
工作台采用浅色纸张界面：左侧为当前文档的任务示意，右侧显示前四份等待文档，下方为双设备实时页数与共享待派发顺序。
浅冷色底区分预览区域，纸张内的蓝、珊瑚、青绿体现内容层次，主要操作与进度统一使用蓝色。纸张由 QPainter 绘制，支持高 DPI；不是生成概念图的截图。
界面启动时依次选择微软雅黑、Noto Sans SC、苹方等实际安装且支持中文的字族，避免中文回退为方框。
点击等待文档可预览它的实际页数、历史元数据与状态。纸张不读取或渲染真实 PDF，图形明确标注为任务示意。
“新建任务”打开原生表单，可录入名称、页数、份数或导入 JSON；“记录”页保留完整任务表、筛选、取消与报表，“设备”页显示连接状态及统计。经营模式通过快速、普通、灵活服务档位表达订单需求。
任务行显示状态徽标、页数进度和简短 ID，悬停可查看完整 ID 与错误详情；空队列显示操作提示。窗口较窄时文档列保持可读宽度，表格改为横向滚动。
右下角“运行日志”可展开或收起事件记录，收起时仍继续接收日志；设备页可重新检查执行器和打开输出目录。
窗口较矮或展开日志时，各页可滚动，操作按钮不会覆盖任务行。Ctrl+K 打开可搜索命令菜单（新建、暂停、三种策略、导出、搜索、页面跳转），F11 切换全屏。
任务入队和等待顺序变化时使用短暂的位置过渡；完成时纸张缩小淡出。无持续循环动效，“减少动效”可立即停止过渡。
等待顺序由后台快照按当前策略（综合调度含累计等待老化）计算；切换策略不会重排正在运行的任务。下方等待条是共享队列，不承诺未来设备归属；预计时间是后台按当前状态的推算，不是准确结束时间。
进度来自 coordinator 聚合的工作进程事件，最终状态以后台快照为准。进度到 100% 不提前标记成功；后台核对原子输出与执行结果后才进入完成状态。

可切换 FCFS、SJF、综合调度。文档队列排序与打印机分配分为两层，等待预览与实际领取共用核心规则，使用后台配置的老化周期；见 [调度规则](scheduling.md)。旧优先级字段仅用于保留历史元数据。
暂停只影响新任务领取，策略与暂停状态均保存到 `state.json`，重开窗口后同步按钮与下拉框。
统计由后台调用 A 的 `statistics()` 计算，窗口起点为持久历史中最早提交时间，终点为后台本次快照时间。
首次等待、成功任务周转、状态计数不会因重开 GUI 清零；吞吐量和利用率随统计窗口继续增长而变化。
导出 JSON 包含完整任务执行区间与时间字段，可独立核算。允许中途切换策略，因此不能作为同负载策略对照实验；正式比较使用 `scheduler-replay`。

## 线程和后台连接

`PrintWindow`/`JobTableModel` 在 GUI 线程，`PrintController` 在专用 QThread 通过 `QLocalSocket` 发命令与读取 JSONL。
有界 IPC 等待、文件解析和报表写入都在该工作线程，值快照通过 `Qt::QueuedConnection` 回到界面。
GUI 不再拥有 Scheduler，也不直接启动 supervisor/worker。

首次连接不到后台且状态目录没有存活的协调者时，通过 `QProcess::startDetached` 启动同目录的 `print-coordinator`。
状态目录的单实例锁避免双窗口重复创建服务。连接异常后重新连接/启动后台，取得完整快照后恢复控制。
命令逐个处理、关联 request_id，断线时不自动重放未获确认的修改操作，提示用户先核对队列。

后台快照包含完整任务、等待顺序、设备槽位、进度、策略、暂停状态、后台时间和统计。GUI 每 300 ms 请求一次，
按换行接收完整 JSON，不假设一次读取等于一条消息。命令上限 8 MiB，回复上限 64 MiB，后台对慢客户端限制待发送缓冲。
每次最多展示 200 条日志，前台保留 500 行。任务表保留选择，不为每个单元格创建 QWidget。

关闭窗口的请求排在此前提交/取消命令后处理，只关闭客户端连接，不终止后台任务。
再次启动并使用相同 `--data-dir` 即可恢复队列视图。停止后台与清理方法见 [clean-up.md](clean-up.md)。

## 批量输入

使用 [gui-batch.json](../examples/gui-batch.json) 的非空 JSON 数组，字段为 title、pages、copies（默认 1）、priority（默认 0）。
整个文件先校验，非法行不会导致部分导入；文件上限 4 MiB，持久队列最多 10000 个任务。
导入时生成新 ID 并立即入队，不保留回放文件的模拟到达时间。
需要比较策略时先暂停，导入相同输入，再选择策略并继续派发。

## 取消、重连与故障演示

运行任务取消由 coordinator 先持久化 attempt 对应的取消标记，确认旧执行停止后进入 Cancelled。
取消与成功提交竞争时，已确认的输出成功优先。重启后检查标记、文件锁和原子输出，避免取消任务重新执行。

默认隐藏故障按钮。`--demo-mode` 仅在 GUI 和所连接后台都允许演示时启用故障注入，后台通过本次 attempt 专属标记
请求 supervisor 结束实际 worker，观察有限重试。普通后台拒绝故障命令。旧的 [单任务 TCP 控制协议](control-protocol.md)
仍可独立使用，GUI 当前主链改用 coordinator 本地 IPC，不再依赖 GUI 心跳维持任务存活。

## 验收步骤

1. 启动 `campus-print --data-dir runtime/gui`，暂停派发，导入示例，然后继续：看到两台打印机的独立进度与等待队列。
2. 暂停新任务派发，选中等待任务取消；再选中控制已连接的运行任务取消，观察“取消中”直到停止确认。
3. 提交空白名称或总页数超过 10000 的任务，看到错误且队列不增加。
4. 使用 `--demo-mode`，选中运行任务点击工作进程崩溃，观察恢复与新 PID；点击控制连接断开，观察自动重连。
5. 导出统计 JSON；将输出目录设为不可写时观察失败反馈，不能把进度满格当成功。
6. 带任务关闭并重开窗口，确认任务、策略、暂停状态与统计保留；验收记录见 [集成验证](validation-integration.md)。
7. 启动老板后台和学生端（相同 `--data-dir`）：学生端上传文件、支付下单，两边看到同一订单和一致的预计时间；暂停派发后学生端显示“恢复后…”。在老板后台的记录页用学生端显示的取件码搜索，应只剩这一笔订单。
8. CTest `gui` 覆盖统一后台的真实提交、运行取消、故障、重连、持久恢复和 5000 项队列交互，以及老板后台的预计显示、记录搜索、设备暂停 / 恢复接单、确认后退款，和学生端的上传、报价、模拟支付、确认后取消与取件流程；另保留单任务 `EventStream` 的任意字节拆包、粘包、非法字段及超长帧恢复测试。
   Windows/macOS CI 还使用原生窗口执行演示流程并保存截图，见 test-evidence 产物。

实际验证记录见 [validation-c.md](validation-c.md)，发布与独立机器验证见 [release.md](release.md)，
项目结束清理见 [clean-up.md](clean-up.md)。

Windows 快速演示入口为 [start-paper-demo.cmd](../start-paper-demo.cmd)，查找和构建步骤见
[纸张工作台 Demo](paper-demo.md)。发布目录不属于 Git 提交，脚本会在缺少可执行文件时给出构建命令。
