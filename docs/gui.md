# 成员 C：界面、线程与验收

关联 [Issue #3](https://github.com/We1chan/campus-print-scheduler/issues/3)。

## 当前可运行功能

两台打印机分别显示文档、尝试状态与页数进度；任务表按 `job_id` 关联，支持等待/运行/完成/失败/取消筛选。
工作台采用浅色纸张界面：左侧为当前文档的任务示意，右侧显示前四份等待文档，下方为双设备实时页数与共享待派发顺序。
浅冷色底区分预览区域，纸张内的蓝、珊瑚、青绿体现内容层次，主要操作与进度统一使用蓝色。纸张由 QPainter 绘制，支持高 DPI；不是生成概念图的截图。
界面启动时依次选择微软雅黑、Noto Sans SC、苹方等实际安装且支持中文的字族，避免中文回退为方框。
点击等待文档可预览它的实际页数、优先级与状态。纸张不读取或渲染真实 PDF，图形明确标注为任务示意。
“新建任务”打开原生表单，可录入名称、页数、份数、优先级或导入 JSON；“记录”页保留完整任务表、筛选、取消与报表，“设备”页显示连接状态及统计。
任务行显示状态徽标、页数进度和简短 ID，悬停可查看完整 ID 与错误详情；空队列显示操作提示。
右下角“运行日志”可展开或收起事件记录，收起时仍继续接收日志；设备页可重新检查执行器和打开输出目录。
窗口较矮或展开日志时，工作台与记录页可滚动，操作按钮不会覆盖任务行。Ctrl+K 打开可搜索命令菜单，F11 切换全屏。
任务入队和等待顺序变化时使用短暂的位置过渡；完成时纸张缩小淡出。无持续循环动效，“减少动效”可立即停止过渡。
等待顺序由后台快照按当前策略（含优先级老化）计算；切换策略不会重排正在运行的任务。下方等待条是共享队列，不承诺未来设备归属或准确结束时间。
进度到 100% 不提前标为成功：必须收到输出提交与监督完成事件、监督进程正常退出 0，且最终输出文件存在。
重试从 0 显示新尝试；无效事件只记诊断，不修改任务状态。

可切换 FCFS、SJF、优先级老化（30 秒增加 1 点；基础优先级越大越优先）。
暂停仅影响新任务领取。等待任务可以立即取消，运行任务通过监督进程停止并确认后取消。
统计直接使用 A 的 `statistics()`，显示本次会话的首次等待、成功任务周转、吞吐量、利用率与任务状态分布图；
空样本均值显示 0，结合图中的样本数量解读。导出 JSON 报表在工作线程原子写入。
会话允许中途切换策略，因此该报表不能作为同负载策略对比；正式算法对比使用 `scheduler-replay`。

## 线程和消息分帧

`PrintWindow`/`JobTableModel` 在 GUI 线程。`PrintController` 移到专用 QThread，之后在该线程创建
QProcess 和定时器，处理调度、文件写入、JSON 导入、日志解析及统计。显式 `Qt::QueuedConnection`
传递值快照与信号，不跨线程持有或修改 QWidget。

每个 supervisor stdout 使用独立 `EventStream`：先缓存字节、按 LF 组完整行、再解码 JSON。
支持 CRLF、空行、UTF-8 多字节拆分和多行合并。校验 schema_version、job_id、事件类型及进度范围。
单帧上限 64 KiB，超限丢弃到下个换行后继续；连接结束的半条消息记错误。stderr 为有界诊断文本。

后台每 100 ms 发一次任务/统计快照，每批最多 200 条日志；前台日志最多保留 500 行。
任务表使用 model/view 和增量行通知，保留选择，不为每个单元格创建 QWidget。
关闭请求也排队交给后台确认，防止“刚点击提交、界面尚未刷新就关闭”的竞态。

## 批量输入

使用 [gui-batch.json](../examples/gui-batch.json) 的非空 JSON 数组，字段为 title、pages、copies（默认 1）、priority（默认 0）。
整个文件先校验，非法行不会导致部分导入；文件上限 4 MiB，会话最多 10000 个任务。
导入时生成新 ID 并立即入队，不保留回放文件的模拟到达时间。
需要比较策略时先暂停，导入相同输入，再选择策略并继续派发。

## 取消、重连与故障演示

已补充可选的[单任务监督进程控制协议](control-protocol.md)，作为与 B 后续持久服务整合的接口。
运行任务的控制状态在各打印机卡片显示；取消请求进入 Cancelling，收到 worker 停止确认和正常退出 130 后才生效。
输出已提交时成功优先。执行器缺失可重新检查，控制 TCP 断开会自动重连；重连后恢复控制、重发待确认的取消意图。
任务进度仍从 stdout 接收，因此控制通道短暂断开不会丢掉进度或终态。

默认隐藏故障按钮。`--demo-mode` 同时启用 GUI 和 supervisor 的演示权限，允许结束指定任务的真实 worker
或断开客户端控制连接，观察有限重试/自动重连。非演示 supervisor 也会独立拒绝故障命令。
GUI 心跳租约过期会停止 worker；这不等于持久服务和应用重启恢复。

持久任务队列、监督服务被外部强杀后的进程树回收与恢复对账仍属于 Issue #2，当前内存队列边界保持明确。

## 验收步骤

1. 启动 `campus-print --data-dir runtime/gui`，暂停派发，导入示例，然后继续：看到两台打印机的独立进度与等待队列。
2. 暂停新任务派发，选中等待任务取消；再选中控制已连接的运行任务取消，观察“取消中”直到停止确认。
3. 提交空白名称或总页数超过 10000 的任务，看到错误且队列不增加。
4. 使用 `--demo-mode`，选中运行任务点击工作进程崩溃，观察恢复与新 PID；点击控制连接断开，观察自动重连。
5. 导出统计 JSON；将输出目录设为不可写时观察失败反馈，不能把进度满格当成功。
6. CTest `gui` 自动覆盖任意字节拆包、粘包、非法版本/ID/字段、超长帧恢复、真实提交/运行取消/故障/重连和 5000 项队列交互。
