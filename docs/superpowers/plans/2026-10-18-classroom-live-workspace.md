# 扫码现场与调度工作台实时联通

用户要求现场多人扫码上传并实时反馈，先用模拟文件走真实链路。继续在 `codex/campus-business-simulation` 实现。

- 手机复用现有上传、报价、模拟支付提交与 1.5 秒状态轮询；提交后明确提示自动进入现场工作台，继续展示本人排队与打印进度。
- 真实店主端新增「现场订单 · 实时」场景，复用 MerchantData 保存的完整后台快照；不改变 IPC 或持久 schema。
- 实时模式自动纳入本场已接受、未取消/失败的订单。三算法在副本中从头重放相同订单规格、原报价、相对到达与期限、真实设备和库存；明确这是同批订单对照回放，手机实际进度仍来自真实后台当前策略。此模式不伪称未来预测，不改变正在打印任务。
- 默认跟随后台时钟和新单；播放/单步/订单定位固定本轮推演，新增订单不会悄悄改动当前推演；「实时跟随」恢复最新批次。新输入在后台线程计算，不阻塞窗口。
- 采用独立的课堂状态目录避免夹入旧订单；脚本参数 `-LiveWorkspace` 打开现场工作台和扫码页，修正源码启动的 Qt 运行库发现。
- 使用模拟 PDF、文本和图片，经真实 HTTP/Cookie/CSRF/报价/提交测试多人场景。验证 UI 自动增单、暂停跟随与恢复、后台策略及状态不被对比修改、完整结果可导出复核。

实现顺序：失败的现场场景检查 → 原始快照模型/纯重放 → 实时 UI 与线程交接 → 启动/模拟上传工具 → 专项、网页与原生联通检查 → 打开现场预演。
