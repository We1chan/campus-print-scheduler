# 校园经营仿真设计

用户于 2026-10-18 确认：保留教学场景，补充完整经营仿真，并在新分支实现供查看。开发分支 `codex/campus-business-simulation`。

## 数据与算法

新增 150、300、600 单三个场景。种子固定为 20261018，使用 mt19937 原始整数抽样，生成作业、实验报告、讲义、社团表格、彩色材料和 A3 图纸。页数和份数依文档类型设定，前三档服务比例为快速 35%、普通 40%、灵活 25%。订单在前四小时到达，八小时闭店。所有数据是合成模拟数据，不是采集的客户记录。

统一使用 `defaultFleet(1250)` 六台异构打印机、充足且相同的纸张供应；`quote()` 决定价格与档位承诺期限。FCFS、SJF、Balanced 直接调用 `replayShop()`。不修改调度算法、权重、后台协议或实际队列，不筛选种子保证综合调度获胜。

## 展示与交互

沿用原场景选择器，新增三个经营项。每个策略使用六条设备轨道；同一订单可跨策略高亮，并显示设备与起止时间。订单每页六条，支持翻页和滚轮。单步按派发/完成事件推进，播放每秒推进四个业务分钟，支持已有倍速、暂停和重置。

用户预览后要求减少时间轴密度：经营时间轴只呈现共同的 30 分钟窗口，每五分钟前移，每个设备最多保留当前及后续三单，已完成订单移出。卡片可暂停并定位到选中策略下该单的开始时刻；其他策略可能在不同窗口执行，完整时间继续显示在底部。完整回放数据、最终评分与导出维持原口径。

右侧始终标为闭店结果，展示平均/P95 观测等待、快速准时率、综合得分、完成数、贡献利润、贡献兑现率和设备利用率。底部展示 Balanced 对两个基线的实际变化，保留负收益或较长等待。未开打订单等待观察到闭店，全部快速单进入履约分母，闭店后完成不结算。评分复用 `shopQuality()` 固定等权口径。

## 导出与验证

JSON 导出包含全部输入订单、种子、生成器版本、设备、库存、观察窗口、输入 SHA-256、每个策略的完整订单历史、设备派发记录和指标。原子保存失败时报告错误。

C++ 专项测试核对教学兼容、场景规模、确定性、原算法轨迹一致性、设备兼容及无重叠、闭店结算和指标。Python 审计复用已有基准审计器，从输出轨迹独立重算等待、期限、成本、利润及综合分。Qt 交互测试覆盖新增场景、翻页和隔离性，使用 Windows 原生截图检查文字与版面。
