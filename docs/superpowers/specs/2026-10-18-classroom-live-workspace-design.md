# 现场实时扫码与调度工作台

用户确认需要扫码提交者实时看到反馈，工作台也实时展示。实现于 `codex/campus-business-simulation`，与此前本地模拟场景共存。

## 数据流与口径

手机使用既有签名 Cookie、CSRF、上传、quote、submit、本人状态轮询。确认模拟支付后，元数据进入同一 coordinator，上传原件和封面留在网关的状态目录。学生不能修改策略、获取其他人的文件或原始队列。

真实店主窗口新增场景 7，通过 MerchantData 保存的原始后台快照取得订单、设备、供应、时间和实际状态。有效订单包含已接受的排队/运行/完成单，排除取消、取消中、失败、退款单。以最早有效到达为相对时间原点，保留原规格、报价和承诺期限；只在副本中清除执行状态，三策略调用同一 replayShop 从头对照。这不是保持当前进度的剩余预测，也不是三套实际打印队列。

当前设备配置和累计供应同时应用于所有对照，观察到最后到达后八小时。输入指纹忽略实际进度与时钟，输入或配置改变时由 std::async 计算；Qt 定时器在 GUI 线程接收结果。只有当前场景、仍在跟随且指纹一致的结果或错误才能更新画面。超出六设备/千单或非默认老化配置时显示原因。

## 交互

默认按后台时钟实时跟随，新单自动出现并更新对照。暂停跟随、播放推演、单步或定位会固定当前批次，真实后台继续接单与执行；点击“实时跟随”更新到最新批次。底部展示实际排队、打印、完成数，与右侧同批重放结果区分。三策略仍共享局部窗口、每设备最多三单、固定评分与完整导出。

每场默认新数据目录；`start-classroom-demo.ps1 -LiveWorkspace` 打开真实工作台和二维码页。脚本优先物理网卡选址，允许 PublicUrl 覆盖，并从所选构建缓存发现匹配 Qt/编译器运行库。手机仍需与电脑互通，二维码不提供公网穿透。

## 验证

Qt 私有后台测试接单、跟随/固定/恢复、源快照和隔离性；模型测试保持原 Running 和报价期限不变。预演工具用独立浏览器身份实际上传 PDF、文本、PNG，执行报价和下单，核对本人状态。源快照、输入哈希与三策略轨迹可由审计脚本独立复算。预演目录及证据都在忽略的 runtime 下，不混入源码或旧课堂数据。
