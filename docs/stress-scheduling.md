# 100 单压力实验与原综合目标的精确求解

2026-10-20：本轮范围是固定 100 单实验与老板端调度工作台。实验及工作台只比较 `fcfs`、`sjf`、`optimal`；真实后台的调度、IPC、持久状态和学生网页不在这次替换范围。

`optimal` 是独立的离线求解结果标识，不对应 `Policy::Balanced`，也不把原加权响应比改名为全局最优。报告状态 `OPTIMAL` 表示原目标已经证明最优；`FEASIBLE` 表示有效排程及已知上下界，界面明确标为“当前最好”。

## 固定压力输入

`tools/generate_stress_schedule.py` 使用固定种子 20261020。先确定分布和种子，再启动求解，不根据求解结果重抽样。100 单含 35 份短单、40 份中单、20 份大批量和 5 份超长单；型号、单双面、档位与到达突发混合。不存在不依赖求解算法的唯一“最复杂”实例，因此以可量化的过载与瓶颈描述压力。

| 项目 | 实际输入 |
| --- | ---: |
| 接受订单 / 打印面数 | 100 / 69,394 |
| 设备 / 营业观察窗口 | 原六台异构设备 / 2 小时 |
| 最快设备耗时总和 / 六台设备窗口容量 | 4.270978 倍 |
| A3 专机工作量 / 该设备窗口容量 | 12.971528 倍 |
| A4 用纸需求 / 库存 | 34,097 / 10,000 张 |
| A3 用纸需求 / 库存 | 9,867 / 3,000 张 |
| 仅有一台兼容设备的订单 | 22 |
| 彩色 / 双面 / 快速订单 | 38 / 72 / 47 |
| 单份订单最小 / 最大打印面数 | 1 / 6,904 |
| 零时刻到达 / 不同到达时刻 | 35 单 / 13 个时刻 |

设备直接使用 `defaultFleet(1250)` 的原能力和速度；报价、承诺期限、逐份双面取整、名义成本与实际设备成本保持原规则。全部订单和总耗材需求均参与分母，不能通过删掉未完成订单提高分数。

## 原目标与约束

保持 `balanced-shop-quality-v1`：等待表现、快速准时率、贡献兑现率等权，详细定义见 [调度目标](scheduling.md) 和 [小实例精确模型](optimal-scheduling.md)。这里的时间均为原生毫秒，没有四组小教学场景的 4 倍展示缩放。

保留到达、设备能力、非抢占、单设备不重叠、单订单至多领取一次、整单预留纸张、A4/A3 独立库存、闭店结算等约束。允许机器主动空闲、订单留队和闭店前开始但闭店后完成；后者减少观测等待，但不贡献营业窗口内收入和快速准时数。

固定输入包含未来到达时间，求解器可以据此安排主动空闲；FCFS、SJF 仍由原生产调度核心按在线规则回放，不给它们预知未来的能力。

## 精确认证方法

令 A 为全部订单等待总和，B 为 nearest-rank P95，T 为准时完成的快速单数，G 为截断到名义潜在贡献 V 的实际完成贡献，e 为接受的快速单数，R = 30 分钟。n 固定为 100。

```text
F = nR/(nR+A) + R/(R+B) + 2T/e + 2G/V
Q = 100F/6
```

无快速单、V=0、空集等边界沿用原评分约定。CP-SAT 使用可选执行区间和 `NoOverlap`，库存使用整单预留线性约束。P95 精确要求至少 ceil(0.95n) 个等待 <= B，且至多 ceil(0.95n)-1 个等待 < B。

默认整数 K = 10^9，可通过 `--scale` 改变整数包络精度而保持原目标及最终认证条件不变。将上式四项分别乘 K 后向下取整并求和为 U，则严格满足：

```text
U <= KF < U + 4
```

第一阶段最大化 U，用它寻找候选并计算安全上界，不能把这个近似整数目标的最优当成原 Q 的最优。

第二阶段对精确有理数候选得分 L，添加 `U >= floor(6KL/100)-3`。任何比 L 更好的原目标排程都必在此范围内。对每个可行 `(A,B,T,G)` 四元组重新用 `Fraction` 计算原分数，再排除已审计的四元组及其支配区域；候选改进时收紧阈值。只有剩余模型得到 `INFEASIBLE`，才标记 `OPTIMAL` 并把原目标上下界设为同一个精确分数。

加强约束包括有向外整数取整的分段弦上界、设备完成任务容量、到达后可用容量和交付窗口内的快速订单容量。它们仅用于剪枝，不改变原目标或删除合法排程。

一般 100 单异构调度包含组合选择和非线性目标，不保证有限时间预算内完成证明。超时保留真实排程、原分数、安全上界和非零差距，程序退出码为 2。分项诊断即使取得最优，也不能单独宣称整体 Q 最优。

## 独立分项边界

对同一个固定 100 单输入，已单独求得：

| 分项 | 已证明的界 | 证据状态 |
| --- | ---: | --- |
| 快速准时完成数 | 最多 34 单 | 分项 OPTIMAL |
| P95 等待 | 至少 105 分钟 | 分项 OPTIMAL |
| 全部订单等待总和 | 至少 83,868 ticks，tick=1,250ms | 求解安全下界 |
| 完成贡献 | 至多 724,491 货币分 | 求解安全上界 |

四项分别取最乐观值，可得原 Q 的安全上界 `375993745957000/8118317209941 ≈ 46.3142466885`。它们可能无法在同一排程中同时达到，因此这不是一份 46.314 分排程，也不是整体最优性证明。证据在忽略目录 `runtime/stress100-component-*.json`。复用边界必须匹配场景哈希、时间粒度、目标分项和界方向，并重新验证其可行排程。

## 基线与证据

`stress-replay` 从 JSON 读取规格，重新调用真实 C++ `quote`、`compatible`、`processingMs`、`directCost` 检查全部输入，再调用 `replayShop` 产生 FCFS/SJF。Python 独立重算评分；工作台加载时还会再次检查输入哈希、设备占用、用纸、到达、开始和完成时间、原生基线逐条派发及最终指标。

| 策略 | 窗口内完成 | 快速准时完成 | 平均 / P95 等待（分钟） | 贡献兑现率 | 综合分 |
| --- | ---: | ---: | ---: | ---: | ---: |
| FCFS | 45 | 10 / 47 | 72.59 / 115 | 8.79% | 18.345566487 |
| SJF | 74 | 27 / 47 | 36.94 / 120 | 16.48% | 35.446326919 |
| 本轮求解当前最好（FEASIBLE） | 72 | 34 / 47 | 43.005 / 120 | 19.37% | 40.753579750 |

**本轮没有完成整体全局最优证明。** 多轮搜索中，带四项边界、资源容量和有理数认证的 1200 秒主求解取得最好的真实排程。原 Q 的可行下界为 `84799058633210/2080775704923`，安全上界为 `665262977/15000000 ≈ 44.3508651333`，尚有约 **3.597285383 分**的差距。第一阶段状态为 `FEASIBLE`，排除更优四元组的第二阶段在预算内为 `UNKNOWN`；不得据此写成原目标已达全局最优。

当前排程已达到快速准时数的理论最大值 34，但平均等待高于 SJF、P95 高于 FCFS。这些结果体现原综合目标的取舍，不能表述为所有指标都更好。最终完整报告在 `runtime/stress100-certified/report.json`，同一报告已发布到工作台默认读取的 `runtime/stress100/report.json`；初轮结果保留为 `runtime/stress100/report-initial-600s.json`。

求解器的最新排程、上下界和完整时间表以 `runtime/stress100/report.json` 为准；未证明时不得将其作为“全局最优结果”引用。工作台不会因为 JSON 策略名为 `optimal` 就显示已证明，还要求状态、精确上下界与重算得分一致。

## 复现

先在个人 Python 环境安装离线优化依赖，原程序不需要安装 OR-Tools：

```sh
python -m pip install -r experiments/optimization-requirements.txt
cmake --build build/ci --target stress-replay campus-print
python tools/generate_stress_schedule.py --output runtime/stress100-input.json
python tools/run_stress_schedule.py --input runtime/stress100-input.json --replay build/ci/bin/stress-replay --output-dir runtime/stress100 --time-limit 1200 --workers 12
```

Windows 可执行文件补 `.exe` 并沿用 Qt DLL 环境。输入文件和输出目录必须为新路径，不覆盖现有订单或结果。若采用本机隔离依赖目录，显式使用与安装依赖相同的 Windows CPython，并令 `PYTHONPATH` 指向 `runtime/optimization-python`，避免把 Windows 轮子交给 MSYS Python 导入。

需要续算时，换一个输出目录，加 `--resume <先前report或progress.json>`；可重复添加 `--certified-bounds <分项报告>`。每轮保留输入/求解器/审计器/可执行文件 SHA-256、基线命令、库版本、时间预算、访问节点和原始分数，以及当时的脚本副本。输入始终固定，不以更换随机种子获得更易证明的结果。多线程限时搜索的中间候选和耗时不保证逐次相同，输入、数学模型、评价口径及最终证明条件保持相同。

启动老板端后打开调度工作台，默认选择 100 单场景。默认读取上溯项目目录的 `runtime/stress100/report.json`；`CPS_STRESS_REPORT` 可以指定另一份报告。“更新求解报告”重新加载文件；界面不在 UI 线程运行优化器，也不调用后台派发命令。100 单分 17 页，三条排程各含六个设备轨道，可以选择订单、播放和单步。
