# 两层调度与三种策略

2026-10-10 起，系统统一使用 FCFS、SJF、综合调度（`balanced`）。文档队列内部排序与文档分配到打印机是两个层次：先决定下一份文档，再为它选择当前空闲且兼容的设备。两层都在 Scheduler 的同一个锁内执行，随后由 coordinator 先持久化、再启动打印进程。

| 策略 | 第一层：文档队列 | 第二层：打印机分配 |
| --- | --- | --- |
| FCFS | 本轮入队时间从早到晚 | 设备编号从小到大，选择第一台空闲兼容机 |
| SJF | `pages × copies` 从少到多 | 选择预计执行时间最短的空闲兼容机；同速选直接成本低者 |
| 综合调度 | 自研加权响应比：档位、等待、期限与收益的加权价值除以打印面数；另有超长等待保护 | 先保留其他订单唯一可用的设备，再依次比较执行时间、直接成本、闲置能力和设备编号 |

队列主键相同，按本轮入队时间，再保持原始插入顺序。所有策略仅考虑已经到达的 Queued 文档，不抢占正在打印的订单。缺纸或没有空闲兼容机的文档保留队列位置；这一轮可以跳过它，让其他设备继续工作。

## 综合队列评分

采用加权响应比，把短单效率、快速履约与经营价值结合。权重使用旧种子 20260923 的模拟负载进行设计，验收另用 20261010/11/12 三个种子，评分口径在验证前固定。参数不是来自真实顾客行为的拟合结果。代码使用整数定点分数，100 个内部单位等于下面的 1 分；等待取到 0.1 分，其余项取到 0.01 分，排序时用整数交叉乘积比较比值，不提前舍入响应比。

```text
加权响应比 = (1 + 服务分 + 等待分 + 紧迫分 + 收益分) / (pages × copies)
服务分：快速 32，普通 16，灵活 0
等待分：floor(10 × sqrt(累计排队毫秒 / agingIntervalMs)) / 10（不封顶）
紧迫分：4 × clamp(1 − max(期限 − now, 0) / 档位承诺时长, 0, 1)
收益分：32 × clamp(预计每打印面贡献分 / 100, 0, 1)
超长等待保护：累计排队达到 8 小时，优先于未达到者；保护组内等待最长者先
```

没有交付期限或已经到期时紧迫分为 0：已失去交付机会的订单不再额外挤占仍可履约的订单，其服务分和等待保护继续有效。档位承诺时长沿用快速 30 分钟、普通 2 小时、灵活 8 小时。收益分中的“贡献分”是整数货币分：锁定报价减去名义纸张和墨粉成本，再除以打印面数；黑白按黑白机耗材估算，彩色按彩色耗材估算。该项在第一层不依赖当前哪台设备空闲；第二层选定设备后再记录实际 `costCents`。

默认老化间隔 30000 ms；等待分按平方根增长，避免繁忙队列完全退化为到达顺序，超长等待保护单独保障长单、灵活单和低价单。累计等待保留到重试，不包含执行时间。旧 `priority` 字段仅作为历史元数据读取、保存和校验，已经不参与排序。支付方式和学号也不参与排序。

目标按用户确认的综合口径验收：在固定经营负载套件上，平均综合得分高于 FCFS 和 SJF，同时展示所有单项和落后场景。单机同到达、没有档位和经营差异时，SJF 对平均等待本身已有优势，不能宣称自研策略在所有负载的每个指标上都占优。持续过载、设备停接或库存不足时，保护是队列顺位保障，不能承诺物理等待上界或全部准时。

## 固定验收评分与实际结果

三个分项等权，最终分数为三项均值乘 100。等待均值与 P95 包括全部接受订单，未开打的订单等待观察到闭店；P95 使用 nearest-rank。快速履约分母为全部接受的快速订单，未完成不能算准时；没有快速订单的同一对照组该项为 1。贡献收益只计闭店前完成并结算的订单，分母是同一批接受订单全部按名义耗材成本完成时的潜在贡献，取值限定到 0–1；潜在贡献为 0 时该项为 0。空集合总分为 0。

```text
等待分 = 0.5 / (1 + 平均观测等待 / 30分钟)
       + 0.5 / (1 + P95观测等待 / 30分钟)
快速履约分 = 按承诺准时完成的快速订单 / 接受的快速订单
贡献收益分 = 完成订单实收减实际直接成本 / 全部接受订单的名义潜在贡献
综合得分 = 100 × (等待分 + 快速履约分 + 贡献收益分) / 3
```

2026-10-10 本机 Release 实际验证：种子 20261010/11/12 × 150/300/600/900 名潜在客户 × 7 种固定订单/优惠选择场景，8 小时窗口、相同六台设备，共 84 个配对场景、252 次真实 C++ 回放。每组的接受订单、报价和期限保持一致；独立 Python 审计从派发记录重算等待、设备兼容、占用、成本、履约和分数，不信任汇总值。

| 策略 | 平均/P95 观测等待（分钟） | 快速准时率 | 贡献兑现率 | 综合得分 |
| --- | ---: | ---: | ---: | ---: |
| FCFS | 129.93 / 302.83 | 34.44% | 69.84% | 41.9642 |
| SJF | 80.67 / 314.60 | 66.68% | 68.32% | 53.5581 |
| 自研综合调度 | 88.09 / 325.36 | 69.81% | 71.16% | **54.9995** |

表中各项都是 84 个配对场景等权平均；P95 也是各场景 P95 的平均，并非合并所有订单后的分位数。相对 SJF，自研平均等待有所增加，换取了快速履约和贡献收益的提升。

自研平均分相对 FCFS 高 31.06%，相对 SJF 高 2.69%。三个种子各自汇总也均优于两者。对 FCFS 为 79 胜 / 5 负；对 SJF 为 52 胜 / 29 负 / 3 平。轻负载和部分所有顾客都选择快速档位的场景仍有取舍，完整原始结果不筛选。数据全部是可复现的模拟经营负载，结论限于上述验收套件和评分口径。

```sh
python tools/run_scheduling_benchmark.py --experiment build/ci/bin/shop-experiments --output runtime/scheduling-benchmark
```

Windows 给可执行文件补 `.exe`。输出目录必须不存在；`summary.json` 包含全部逐场景指标、胜负统计、输入参数、实际命令和执行文件/报告哈希。本机证据在忽略目录 `runtime/two-layer-scheduling/benchmark-v1/`。核心质量计算位于 `shopQuality()`；CTest 的 `shop_experiments` 使用同样的 84 组验收套件，要求平均综合分必须高于两个基线，防止后续修改破坏目标。

## 综合设备分配

先对已经到达、库存足够的等待文档统计：它在当前空闲设备中是否只有一台兼容机。对候选设备，优先选这种独占需求较少者。例如黑白单在队列前面、彩色单在后面，同时有黑白机和彩色机空闲，黑白单会留出彩色机；两份文档便能同时开始。A3 和双面能力按同一规则处理。

独占需求相同，优先最快设备；同速时选择直接成本低者；再减少多占用的 A3、彩色、双面能力；完全相同用设备编号保持稳定。该步骤只能为第一层选中的文档选设备，不会因为某份文档在某台机上的收入更高而绕过队列顺序。

设备占用、兼容性、库存预留仍原子检查。同一文档不会被两个打印机领取；重试沿用预留用纸，取消或最终失败释放预留。已有状态机、令牌、退款和支付规则保持有效。

## 接口、迁移与实验

- C++ `Policy` 只有 `Fcfs`、`ShortestJobFirst`、`Balanced`；IPC、持久状态和新实验报告使用 `fcfs`、`sjf`、`balanced`。
- 旧 `priority`、`deadline`、`revenue` 策略名作为输入别名映射到 `balanced`；旧状态加载不重建订单、金额或历史，下一次保存和 IPC 回复使用规范名称。IPC 信封及持久 schema 不变。
- `waitingOrder()`、`claim()`、`claimFor()` 共用第一层比较；经营 `claimFor()` 再执行第二层。后台报价与预计等待、教学工作台和 `replayShop()` 都调用同一核心。
- `scheduler-replay` 默认输出三种策略。同构模式没有经营报价，综合调度主要表现为等待与短单权衡；`priority` 不再制造人工紧急度。
- `shop-experiments` 默认仍生成 21 组实验（7 种场景 × 3 策略）；`--input` 每个固定文档负载输出 3 组。历史实验材料保留原策略和原数值，不能作为新版算法的结果。

相关测试包括三策略顺序、档位/期限/收益影响、老化与重试等待、稀缺设备并行利用、设备和库存并发领取、旧状态/IPC 别名迁移，以及预计与回放逐项一致。完整运行方式见 [经营说明](shop.md)；公共契约见 [interfaces.md](interfaces.md)。
