100 单扩展和工作台现行三行比较见 [100 单压力调度](stress-scheduling.md)。本页保留四组六单的精确证明与原有基线历史；工作台当前第三行使用这些已证明排程，不再运行 Balanced。

2026-10-20：对调度工作台当前四组教学订单，直接从 `makeDispatchDemo()` 导出输入，用精确有理数枚举求解。四组均得到 `OPTIMAL`，最优上界等于可行解下界，差距为 0。该工具用于固定订单集合的离线参照，实时策略和 IPC 仍为 FCFS、SJF、Balanced。

## 目标与时间口径

沿用 [现有综合验收](scheduling.md) 的 `balanced-shop-quality-v1`，不改变权重来迎合结果。设接受订单数为 n，营业截止为 H，等待参考 R = 1,800,000 ms（30 分钟）。

```text
w_j = 已开始时 S_j - r_j；未开始时 H - r_j
平均等待 = sum(w_j) / n
P95 = 排序后第 ceil(0.95n) 个 w_j

W = 0.5 / (1 + 平均等待 / R) + 0.5 / (1 + P95 / R)
E = 闭店前且交付期限内完成的快速订单数 / 全部接受的快速订单数
V = sum(max(0, 锁定报价 - 名义直接成本))
G = 闭店前完成订单的锁定报价减实际设备直接成本之和
C = clamp(G / V, 0, 1)
Q = 100 × (W + E + C) / 3
```

没有快速订单但有订单时 E = 1；V = 0 时 C = 0；空订单集 Q = 0。所有接受订单始终保留在分母中。计算使用 `Fraction`：例如平均等待不先转浮点，P95 也不用插值。

这里统一使用工作台的**展示时钟**。现有模型把核心 5 秒/页乘以 4，显示为 20 秒/页，即每分钟 3 页；导出时直接读取已经缩放的派发记录，不把展示速度当成可配置打印机参数。R 固定为展示时钟的 30 分钟。四组教学场景的评分不能与此前六台设备、8 小时经营负载套件直接合并比较。

## 数学约束

订单 j 的到达时刻为 r_j、开始时刻为 S_j，设备 m 上的执行时间和成本分别为 p_jm、c_jm。二元变量 x_jm 表示订单是否被派发给该设备；允许部分订单在观察窗口内保留排队。

1. 每份订单至多派发一次：`sum_m x_jm <= 1`。
2. 设备必须在线并满足 A3、彩色、双面要求；不兼容的 x_jm = 0。
3. 派发的订单满足 `r_j <= S_j < H`，完成时刻为 `C_j = S_j + p_jm`。
4. 同一设备上的任意两份订单执行区间不能重叠；执行不抢占。
5. 每种纸型的已派发订单实际张数总和不能超过库存。双面为 `ceil(pages / 2) × copies`，逐份向上取整。
6. 开打时整单预留用纸；闭店前开始但闭店后完成的订单仍占用库存，其等待按实际开始计，但不计闭店贡献和快速准时。
7. 恰好 H 完成计入结算；恰好 H 开始不允许。r_j = H 的接受订单仍保留在评分集合中，观测等待为 0。

设备状态、耗时、报价、期限、库存和订单到达时间在本次求解中固定。当前教学订单为新订单，没有运行历史、失败、退款和补货。为保证下述简化证明成立，工具校验订单在每个兼容设备上的完成净贡献均非负；不满足时拒绝求解，不输出错误的最优保证。

Balanced 的加权响应比分数是原启发式的选择规则，并非本模型的额外硬约束。精确求解直接比较最终 Q，并允许主动空闲以等待已知未来订单。教学窗口均不足 15 分钟，不会触发原策略的累计 8 小时保护。

## 为什么能证明全局最优

固定任意可行排程的每台机器上的订单序列，从序首起令：

```text
S_j = max(r_j, 同一设备前一份订单的完成时刻)
C_j = S_j + p_jm
```

这样将订单尽可能左移：每个已开始订单的等待只会减少，快速准时数只会增加，闭店完成的非负贡献只会增加；P95 对每个等待分量也是单调的。库存无补货且预留不释放，总量约束保持成立。因此，对每组机器序列，只需比较这一种最早开始排程，就包含至少一个全局最优代表。

求解器完整枚举“选择哪些订单开打、分配到哪台机器、每台机器内部的顺序”，不枚举毫秒网格。跨设备派发按 `(开始时刻, 设备编号, 输入顺序)` 规范化，避免同一排程因插入顺序不同重复出现。未派发订单和空排程也纳入比较。

当前每场景单机 6 单，枚举节点数为：

```text
sum(k=0..6) 6! / (6-k)! = 1 + 6 + 30 + 120 + 360 + 720 + 720 = 1957
```

每个候选用有理数比较 Q，穷尽后最大值就是全局最优值。报告保留精确分数、访问节点数、上下界、差距及是否穷尽。达到节点预算时只返回 `FEASIBLE` 和保守上界 100，退出码为 2，不声称已证明最优。该指数枚举工具限制最多 10 单，默认每场景 1,000,000 节点。
