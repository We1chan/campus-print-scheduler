# 现场实时订单与调度工作台

## 2026-10-18 当前实现

链路为：扫码加入 → 真实文件上传 → 后台报价 → 模拟支付下单 → 同一 coordinator → 手机状态轮询与店主端原始快照 → 三策略同批重放。

真实店主端场景菜单新增「现场订单 · 实时」，从 `MerchantData::dispatchSource()` 读取 `ViewState::shop` 保存的完整快照。输入指纹覆盖文档规格、原报价/期限、设备与库存；订单增删或配置变化触发后台线程重算，时钟与实际进度变化只刷新时钟和实际数量。所有结果在 GUI 线程交接，过期任务和固定批次期间的迟到结果不会替换画面。

本场有效订单保留实际订单 ID，另用 S001 等短标签显示；模拟执行清零仅作用于副本。三种策略共用同批订单、相对到达、锁定报价/期限和当前设备/库存，调用现有 `replayShop()` 与 `shopQuality()`。已完成但未退款订单仍参与本场重放；取消/失败/取消中/退款订单排除。原始快照随报告导出，审计脚本核对快照到输入的映射，再从实际回放轨迹复算指标。

手机看到的排队、预计取件和进度来自真实后台；工作台右侧是对照重放结果，底部另显示后台实际数量。此功能不构造“正在运行的实际三套队列”，也不是基于已打印页数的剩余任务预测。历史实际执行不被修改。源配置或网络异常会显示同步说明；工作台最多支持六设备、千单和默认老化配置。

启动与模拟上传见 [classroom-demo.md](classroom-demo.md)。以下保留早期调研，描述的“保留正在打印进度的剩余队列预测”是另一种尚未接入该工作台的口径。

## 2026-10-09 历史可行性调研

2026-10-09 核对当前源码并向现有 v1 店铺数据目录执行只读 `snapshot`。接口正常返回，当时为 0 个订单、6 个设备槽位；没有向真实队列提交测试单或改变策略。

| 展示内容 | 已有能力 | 接入工作 |
| --- | --- | --- |
| 当前订单、文件名、规格、优先级、期限、金额、状态、进度 | `snapshot.jobs` 完整订单元数据 | 复用现有 controller 状态更新，增加调度页面的数据转换；较容易 |
| 当前策略、候选顺序、设备、库存、当前时间、开始与完成预测 | `policy`、`waiting_order`、`fleet`、库存、`now_ms` 及订单预测字段 | 复用现有快照；未知预测、暂停和库存受阻需要明确显示 |
| 同一真实队列的三种策略预计对比 | 已有 `estimateWaits(jobs,now,EstimateOptions)` 核心函数，按真实两层领取规则在副本计算 | 暂无直接返回三套结果的 IPC 接口；可在前端后台线程用同一快照调用三次，无须改变真实策略。若计算统一放在服务端，则增加只读对比请求 |
| PDF、Word 等文档正文或原件预览 | 现有订单传输没有原件字节或可用源文件路径 | 需要新增原件共享/上传及读取机制，当前不能只靠 snapshot 实现 |

建议新增“当前队列”场景，读取后台实时订单并提供“以当前快照比较”。FCFS、SJF、综合调度的三种预计共用同一时刻、设备、库存、正在打印任务及其已完成页数；不允许为了比较实际切换后台三种策略，也不把正在打印的订单重新排队。预计结果明确标识为预测，保留后台真实运行的单独状态。

当前教学图采用单台打印机、六张示例卡片。真实后台支持多台并行设备、不同能力及更长队列，因此完整展示需要调整并行时间轴和长队列浏览，工作量中等；基础订单信息接入则较容易。已完成订单可供历史查看，三策略预测主要针对正在打印和排队订单。

依据：`src/coordinator/main.cpp` 的 `snapshot()`、`src/gui/print_controller.cpp` 的 `applySnapshot()`、`include/cps/core/estimate.hpp` 和 `docs/interfaces.md` 的等待预测接口。当前 UI 层 `MerchantData::Order` 未保留所有核心字段，接入时应保留完整原始快照，不从缩减后的展示字段重造任务。
