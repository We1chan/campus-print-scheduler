# A：个人讲解与答辩提纲

本材料对应 @We1chan 的调度、状态接口、统计和负载回放部分。先理解下面的代码与手算例子，再用自己的话讲解；最终学校模板、姓名学号和团队联调截图确定后可补入总报告。

## 1. 两分钟讲解顺序

1. **问题与边界。** 两台设备共享等待队列，任务有页数、份数、到达时间和优先级。我实现非抢占的 FCFS、SJF、优先级老化，以及线程安全的领取/取消/重试状态接口。实际文件输出与故障恢复由 B 的进程层执行，GUI 由 C 展示。
2. **关键实现。** 选择任务和改为 Running 在同一个互斥锁内完成；每次领取递增 attempt。运行中取消先进入 Cancelling，等执行器确认停止；过期 attempt 的回调不能完成新一轮任务。快照先校验完整历史再载入。
3. **验证与结论。** 新增 26 个命名测试场景，通过手算、并发竞争、非法快照和真实 CLI 验证。三个历史映射窗口中，SJF 的平均等待更低，但最长等待更高。压力场景里缩短老化周期改善低优先级大任务的等待，同时增加部分紧急任务等待。
4. **局限与合作。** SDSC 是计算日志，页数为人工映射；回放没有故障或真实设备开销。当前 GUI 与独立 coordinator 仍待接通，A 的独立验收和团队端到端验收分别记录。

## 3. 常见问题

**为什么是非抢占？** 已经分配的任务继续占用设备，`claim` 只选择 Queued 任务，切换策略只影响下一次领取。中途取消是用户请求停止的独立协议；实现中没有因高优先级到达而抢占当前打印。

**三种策略怎么选，并列怎么办？** FCFS 按本轮入队时间；SJF 按 `pages × copies`；优先级老化按 `priority + floor((accumulatedWaitMs + now - queuedSinceMs) / agingIntervalMs)`，数值大优先。主键相同按入队时间，仍相同保留提交顺序。重试更新本轮入队时间，已有等待继续累计用于老化。

**老化为什么能帮助大任务，为什么不说绝不会饥饿？** 纯优先级会反复选择紧急任务；等待加分提高旧任务的竞争力。实际效果取决于周期、优先级差、到达流与设备容量。本项目有限压力实验显示 1 秒周期有效改善该大任务延迟，30 秒周期没有；不能由有限样本证明无限输入的性质。

**两个打印机同时领任务，会不会重复？** `claim` 在同一锁内扫描并把选中任务改为 Running。另一个线程拿到锁时已不能再次选择它。不能先取快照、在锁外选任务再更新，因为这会产生检查与修改之间的竞争。临界区内没有文件或进程 I/O；快照返回副本，UI 不持有内部引用。

**为何完成回调要带 attempt？** 同一个 job_id 重试后还是同一业务任务，但已经是新的执行轮次。旧进程迟到的成功、失败或取消消息必须被拒绝。`attempts` 每次领取递增，回调必须匹配当前活动轮次；重试次数包含首次执行，有上限。

**取消和完成同时发生怎么办？** Queued 可以直接 Cancelled；Running 先 Cancelling，执行器确认停止后才能 `acknowledgeCancel`。若仍处于活动状态且已经确认原子输出完成，成功 `finish` 可以使 Cancelling 转 Completed。核心不自行判断输出文件，B 必须按协议核对输出与进程再回调；若已确认取消成为终态，后续回调会被拒绝。不要把按钮点击直接等同于设备已停止。

**快照恢复是不是已经实现了持久化？** A 只定义、校验并加载 Job 快照，要求目标调度器为空，非法数据整体拒绝。写磁盘、锁文件、原子提交、重启检查输出以及孤儿进程处理由 B 实现。加载到 Running 不代表旧进程仍然存在，必须由执行层对账后决定完成、重试或取消。

**首次等待和累计等待有什么不同？** 首次等待从提交到第一次运行；累计等待是各轮排队时长之和，不包含运行时间。本次无重试实验中二者相同。有重试时要展示累计等待、运行区间和周转；不能把失败执行耗时误算为排队。平均周转和平均累计等待只对窗口内成功完成的任务统计，首次等待按窗口内首次开始的任务统计。

**为何用模拟时钟，而不直接 sleep 测时间？** 调度器接受显式时间和注入时钟，回放跳到下一次到达/完成事件，所以速度不依赖真实打印时长，结果可重复。真实 sleep 受机器负载影响，不适合精确指标断言。模拟时间、实际系统耗时和真实设备计时必须分开。

**算法复杂度和不足？** 当前用 vector 保存任务，每次 `claim` 扫描全部已保存任务，O(n)；所有任务逐次选择最坏形成 O(n²) 的比较工作，适合本课设的受控规模。若扩展到长期大队列，应分离终态历史、优化索引，同时处理老化键随时间变化的问题。不要声称当前系统已做大规模性能优化。

**为什么 SJF 平均更低，却不能直接选它？** 短任务先完成能让许多任务少等，但长任务可能反复延后。第一窗口平均等待约 197.199→50.635 秒，最长等待却约 605.530→1738.980 秒；压力场景 p95=0 仍有一个任务等 30 秒。需要同时看平均、尾部、紧急程度和公平性。

**数据是否真实、是否有真实打印机？** 源文件是真实历史计算作业日志；打印页数、优先级和到达压缩是明确记录的人工映射。执行器输出文本模拟打印。不能称为真实校园数据，也不能声称物理纸张 exactly-once。
