# 里程碑与验收

2026-09-23 起以 [经营设计与验收](shop.md) 为当前范围：订单规格 → 分档报价 → 异构设备匹配 → 经营统计 → 策略/优惠实验。原有故障恢复作为基础能力保留，降低后续投入优先级。下面两周计划为早期版本的历史安排。

按两周集中开发安排，可按实际课程日期平移。

## 最终验收场景

1. 并发提交多份长短任务，两台打印机正常工作，无重复领取。
2. 同一批输入分别运行 FCFS、SJF、老化优先级，输出等待与周转统计。
3. 主动结束工作进程，观察新 PID、有限重试和任务最终状态。
4. 结束协调服务，重启后恢复等待/处理中任务，已完成任务不重复执行。
5. 再开一个相同服务实例，拒绝重复占用状态目录。
6. 中文文档名、中文空格路径、空队列、只读目录、非法 JSON 都有明确结果。
7. 三人使用各自身份提交；每个人讲清一段实际代码、一项实验、一个失败与改进。

第 4、5 项针对后续持久服务，当前 v0.1 还未完成；当前已测试的是单任务 supervisor / writer 文件锁。

课件将个人答辩权重列为 60%；实验记录应来自真实运行，并保留输入负载和代码版本。课件还提到 Gitee 提交，本次按用户要求使用 GitHub，正式提交前按课程渠道导出或添加对应远端。
