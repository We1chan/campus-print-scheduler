## A：调度与性能分析

当前进度：优先级老化、取消/重试状态接口、快照加载、统计和负载回放已实现，详见 `docs/replay.md`。下列交付项中的新增自动化用例、正式实验材料及与 B / C 的联调仍待完成。

拥有 `include/cps/core/`、`src/core/`、`tests/core_tests.cpp`。新增统计放 `src/metrics/`，回放工具放 `tools/`。

在已有 FCFS / SJF 和互斥队列基础上交付：

1. 优先级 + 等待老化，明确优先级方向、老化周期和并列规则。
2. 取消等待任务的状态机；打印中的取消由 B 执行、C 发起，A 约定合法状态转换。
3. 记录 submitted / first_started / finished 时间，计算平均等待、周转时间、吞吐量和设备利用率。
4. 同一负载、同一打印速度、同一设备数下比较策略；保存输入参数和实验结果，保证可复现。
5. SDSC SWF 到模拟打印 JSON 的转换与来源记录。SDSC 是计算负载，转换页数须明确是人为映射。

验收：乱序到达、同时间同长度、长期等待大任务、多线程并发领取、空队列全部有测试；同任务不能被两个打印机领取。统计使用可控时钟测试，不能依赖真实 sleep 得出精确结果。

独立答辩：非抢占调度、饥饿与老化、临界区、性能指标和算法取舍。

给 B：状态机和可序列化 Job 快照。给 C：调度策略、队列快照、统计 DTO。避免让 UI 持有核心内部数据引用。

## B：进程、守护与持久化

拥有 `src/runtime/`、`src/worker/`、`src/supervisor/`、`src/platform/` 及相应头文件；负责进程集成测试的运行逻辑。

当前进度：已实现完整 Scheduler JSON 快照、`print-coordinator` 独立后台协调进程、QLocalServer/QLocalSocket JSONL 控制协议、单实例锁、先持久化再执行、Running/Cancelling 启动恢复对账、attempt 唯一取消 marker、supervisor 取消处理、POSIX coordinator daemon，以及相应状态/协调器集成测试。现有 GUI 尚未切换到该 IPC，因此与 C 的联调仍是下一步。

在已有单任务 supervisor / worker、文件锁、原子输出基础上交付：

1. 建立持久队列与独立后台协调服务，把内存队列从 GUI 生命周期中分离。
2. 开机不要求自启；手动启动监督服务即可。服务异常重启后，未完成任务按有限次数重新排队。
3. 分离业务状态与文件状态：先持久化领取，再执行；重启时根据持久记录与原子输出对账。
4. 进程心跳、超时、退避重启、人工取消和正常退出清理；父进程退出不得遗留无主工作进程。
5. 统一文件锁和单实例策略。POSIX 实现传统 daemon；Windows 原生保留前台监督，Windows Service 是可选扩展。

验收：worker 被杀、协调服务被杀、输出目录不可写、第二实例争锁、重启上限、服务正常退出、中文路径都有可重复步骤。模拟输出使用同一 job_id 原子替换，不能宣称真实纸张打印 exactly-once。

独立答辩：进程树、IPC、守护与普通后台线程的区别、互斥文件锁、崩溃一致性和恢复边界。

给 A：持久化接口和单调时钟抽象。给 C：带 schema_version 的事件流、控制命令和错误码。不要让 C 直接读写队列数据库。

## 接口与评审规则

- 直接在 `main` 开发并及时提交推送，不要求 PR；开始工作和推送前按 `CONTRIBUTING.md` 同步远端。
- `docs/interfaces.md` 是共同契约，接口改动与文档放在同一提交，并请相关成员核对。
- 核心 Job / 状态机由 A 提案、B 评审；事件协议由 B 提案、C 评审；构建改动由 C 提案、至少另一平台成员验证。
- 轮换评审：A 评 C、B 评 A、C 评 B；复杂公共接口三人共同看。
- 每人每周提交一个可运行增量、对应测试和一个答辩素材。截图和计时必须来自实际运行。
- 推送后检查三平台 CI，失败及时修复。这是团队约定，目前没有声称 GitHub 已强制启用分支保护。
